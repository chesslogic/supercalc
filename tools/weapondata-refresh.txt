Weapon data refresh notes
=========================

Source of truth
---------------
The app now loads weapon data from the checked-in file:

    weapons\weapondata.csv

That file is the source of truth for the app. The old Google Sheets export is
now just an import source, not the runtime dependency.


Why this changed
----------------
Previously the app fetched a live CSV from Google Sheets at runtime. That made
the site dependent on an external spreadsheet and made it awkward to add local
fields like `RPM` for TTK work.

Keeping the CSV in-repo makes the app self-contained and lets future edits be
reviewed and committed alongside code changes.


Refresh workflow
----------------
For a report-first patch refresh manifest, run:

       python .\tools\run_patch_refresh.py --run-id <patch-or-date>

This writes review artifacts under `tools\artifacts\patch_refresh\...` and does
not modify `weapons\weapondata.csv` or `enemies\enemydata.json`.

1. Download the latest Google Sheets CSV export from:

       https://docs.google.com/spreadsheets/d/e/2PACX-1vTeLqZ5-maEmzrM6SUDMRXpHEhV0tQImiBdgMCil9lSA11IiY_nGdamE54W7DAiSXn1XuJljdF4P537/pub?gid=0&single=true&output=csv

2. Replace `weapons\weapondata.csv` with that export.

3. Generate a fresh `filediver` entity/component dump:

       Set-Location C:\GitHub\filediver
       go run .\cmd\tools\components\entity-component-settings-json-dumper > C:\temp\entity-component-settings.json

4. Merge RPM values from the dump into the checked-in CSV:

       Set-Location C:\GitHub\supercalc
       python .\tools\merge_weapon_rpm_from_filediver.py --dump C:\temp\entity-component-settings.json --csv .\weapons\weapondata.csv

5. Before editing checked-in datasets, run the report-first weapon refresh
   helpers with the checked-in override rules:

       python .\tools\ingest_wikigg_attacks.py --output .\tools\issues\wikigg-stratagem-attacks.json
       python .\tools\build_wikigg_validation_reports.py --skip-enemy

   The ingest and validation reports load `tools\weapon-refresh-rules.json` by
   default. That file is the machine-readable place for exact alias/status
   cleanup knowledge that should affect report classification only:

   - `attack_name_aliases` for source/CSV attack names, including x-count and
     mounted-weapon naming differences.
   - `entity_name_aliases` and `code_aliases` for vehicle, exosuit, mounted, or
     renamed rows.
   - `status_rewrites` for safe status spelling cleanup/removal in projections.
   - `review_required` and `manual_grouping` for cases that must stay
     human-reviewed instead of automatically written.

   To preview observed falloff artifact rows against `weapons\falloff.csv`
   without overwriting it:

       python .\tools\weapon_refresh_rules.py --output .\tools\artifacts\falloff-refresh-preview.json

   Use `--rules <path>` to test proposed rule changes and `--no-rules` on the
   ingest/validation helpers when you need a raw baseline report.

6. Review unresolved rows, alias-classified rows, status rewrites, falloff
   preview differences, and other odd values. Only edit `weapons\weapondata.csv`
   or `weapons\falloff.csv` after reviewing the report output.

7. Use wiki raw JSON only as a fallback/audit source for gaps that `filediver`
   does not cover cleanly. The current best raw source is:

       https://helldivers.wiki.gg/wiki/Module:Decodedata-Weapons/data.json?action=raw

   You can pass it directly to the merge helper when you want wiki backfills:

       python .\tools\merge_weapon_rpm_from_filediver.py --dump C:\temp\entity-component-settings.json --csv .\weapons\weapondata.csv --wiki-url https://helldivers.wiki.gg/wiki/Module:Decodedata-Weapons/data.json?action=raw

8. Run tests before committing.


Patch 1.007.000 / Castellan's Creed audit
-----------------------------------------
The Castellan's Creed rows were audited against the current wiki.gg raw attack
module revision 128924 (2026-08-14 04:29:32 UTC) on 2026-08-16:

    https://helldivers.wiki.gg/wiki/Module:Decodedata-Attacks/weapons%20data.json?oldid=128924&action=raw

The decoded records map to the CSV as follows:

- `R/40-K_P` is one projectile at 275 DMG, 40 DUR, AP 3, and 10/20/14
  demo/stun/push, with 210 RPM and no status. The Hot-Shot durable value is
  specifically `R/40-K_P_dm.dmg2 = 40`; a blank durable field would be treated
  as zero by the calculator. Its projectile has one pellet, and cleavage is not
  multiplied because the calculator has no multi-target model.
- `P/40-K_P` is 325/115/AP 4 with 20/35/15 forces, and its linked
  `P/40-K_P_IE` explosion is 175/175/AP 3 with 10/35/5 forces. Both share the
  weapon's 150 RPM and have no status.
- `40-K MELTAGUN_B` is a 2600/2600/AP 7 beam with 30/40/40 forces and
  `FlamerSlowed` plus `Fire_Panic`.
- `G/40-K MELTA MINE_E` is one 2000/2000/AP 7 explosion with 40/40/40
  forces and no status.

The Meltagun row stores 2600 DMG/DUR as damage per second. Its raw
`beam_fire_rate = 50` metadata is intentionally not written to the CSV RPM
column: continuous beam rows use the calculator's beam tick cadence, while RPM
is reserved for discrete firing cycles. The attack's decoded 15m beam range is
modeled as a hard calculator limit. TTK starts when sustained beam damage
begins; the decoded charge stages are not converted into an invented startup
delay, and reload/target-acquisition time is also excluded.

The Bolt Pistol keeps `P/40-K_P` and `P/40-K_P_IE` as separate projectile and
explosion rows for armor and durable-zone resolution, then packages them once
per trigger pull. The Melta Mine keeps only the decoded
`G/40-K MELTA MINE_E` explosion; no second damage event is assumed from its
visual sequence.

The four current wiki weapon pages list only their 1.007.000 addition through
2026-08-16, with no later balance entry. Armor passives such as True Grit and
cosmetic Warbond items are intentionally omitted because this dataset and
calculator do not model armor/passive or cosmetic effects.


RPM column notes
----------------
The loader already recognizes these header variants:

- `RPM`
- `ROF`
- `Fire Rate`
- `Rate of Fire`
- `Rounds per Minute`

The preferred current path is:

- keep `RPM` in `weapons\weapondata.csv`
- populate it automatically from `filediver` where possible
- use wiki data only for backfills or validation

The first pass should accept a clear/default scalar RPM even if it does not
perfectly model bolt cycling or animation timing. Continuous beam and spray
weapons can stay blank until they have a better cadence model.


Patch metadata
--------------
Because the app now loads a stable local filename, it no longer relies on the
Google Sheets response headers to infer patch metadata.

If you temporarily point the app at a versioned filename, the loader can still
extract a version token like `1.006.003` from the filename, but the stable
checked-in path should remain `weapons\weapondata.csv`.
